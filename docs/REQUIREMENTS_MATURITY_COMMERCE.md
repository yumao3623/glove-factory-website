# JS Meilai 国际手套独立站成熟电商需求文档

**版本：** 0.2（中文修订版）　**日期：** 2026-09-12　**状态：** 直接执行基线

## 一、项目目标与范围

JS Meilai 是面向海外婚纱、礼服、舞台、儿童礼服和配饰采购商的手套工厂独立站。本项目在保留现有产品溯源、审核和素材许可边界的前提下，把原来的“展示/询盘预览站”升级为成熟的国际 B2B 电商：用户可以浏览目录、组合筛选、查看多图详情、建立购物车或询价清单，并在具备真实商业数据后进入支付。

Cornelia James 仅作为交互和信息架构参考：借鉴左侧筛选、顶部公告条、分层导航、地区/语言、搜索、账户、收藏、购物车、产品详情、推荐商品、评价和材质色卡等模式；不得复制其品牌、文案、图片、评价、Logo 或视觉资产。公开内容只能来自 JS Meilai 已批准资料、授权图片或明确标记的 AI 装饰素材。

## 三、信息架构与页面

顶部包含公告条、地区/货币/语言、搜索、账户、收藏和购物车。主导航分为 Shop（全部、精选、婚礼手套、Opera/晚礼服、舞台/服装、儿童礼服、婚礼头纱）、Bespoke（OEM/ODM、私人品牌、染色、装饰、包装、打样）、Factory（能力、质量、材料、包装、合规）和 Guides（尺寸、材料、保养、婚礼搭配、采购说明）。

必需页面：`/`、`/products/`、`/products/[slug]/`、`/collections/[family]/`、`/custom-manufacturing/`、`/factory/`、`/contact/`、`/privacy/`、`/terms/`、`/shipping/`、`/returns/`、`/cart/`、`/checkout/`、`/account/`、`/account/orders/`、`/guides/size-guide/`、`/guides/materials/`、`/swatches/`。

## 四、目录、分类与筛选

桌面端采用左筛选栏、右产品网格；移动端筛选栏变成抽屉。筛选支持同一分类多选、不同分类交集、URL 查询参数、可删除条件标签、清除全部、结果数量、排序和网格密度。无结果时给出移除条件的提示。

筛选项来自批准数据：产品族（婚礼、Opera/晚礼服、舞台/服装、儿童礼服、头纱）、颜色、材料（缎面、真丝、蕾丝、Tulle、天鹅绒、棉等）、长度（腕长、手链长、前臂、肘长、Opera 和确认的数值）、指型（全指、露指、半指）、场合、装饰、尺寸和年龄组。价格、库存、MOQ 及可售状态只有在商业事实审核后才显示。未知或待确认字段不得进入筛选。

产品卡必须展示批准图片、名称、已确认的材料/长度、颜色以及详情和询价入口。不可把未审核图片、认证、产能、现货或交期当作事实。

## 五、产品详情和截图交互

PDP 包含多图画廊、缩略图、放大/灯箱、名称、价格状态、颜色色卡、尺寸指南、长度、材料、指型、可选装饰、数量、加入购物车、收藏、询价、配送提示、规格折叠区、相关推荐和最近浏览。颜色/材料/长度/类型可单选，装饰和服务可多选；不可用选项有禁用态和说明。

购买路径仅对有批准价格和库存或定制规则的产品开启；其他产品显示询价。评价只有在真实订单和评价数据存在后开启。色卡/样品页展示材质图片、颜色、价格状态和购物车/询价入口。搜索、账户、收藏和购物车抽屉必须支持关闭、Esc、焦点管理、键盘和移动端。

## 六、B2B 询价

询价字段包括联系人、公司、国家、工作邮箱、产品/变体、数量、目标交期、材料/颜色/尺寸、定制、包装、附件、备注、隐私同意和独立的营销订阅。详情页和购物车可预填产品上下文。状态为 `new`、`qualified`、`quoted`、`sample`、`won`、`lost`，状态变化写入审计记录。服务端校验、限流和防滥用必须开启；未授权邮件供应商时仅保存本地预览记录，不宣称发送成功。

## 七、数据库、账户和支付

获得项目归属和环境变量后使用 Supabase Postgres、Auth、Storage。核心表为 `products`、`product_variants`、`facets`、`product_facet_values`、`media_assets`、`customers`、`addresses`、`carts`、`cart_items`、`orders`、`order_items`、`payments`、`rfqs`、`rfq_items`、`wishlists`、`reviews`、`content_pages`、`audit_events`。公共查询只能读取 APPROVED 产品和已批准媒体；RLS 按客户、运营角色和订单归属隔离；每个产品保留来源 listing、素材许可、证据状态和变更记录。

Stripe Checkout 为默认支付方案。服务端创建 Checkout Session，Webhook 验签后更新订单和支付状态；本站不接触银行卡号和 CVC。地区、货币、税费、VAT/税号和免税审核均为订单字段。没有 Stripe 凭据时只能显示“本地预览结账”，不得伪造支付成功。账户后续支持邮箱无密码和 Google 登录，访客购物车登录后合并。

## 八、素材与视觉系统

沿用 Editorial Utility / Refined E：不对称编辑构图、真实产品图、清晰 B2B 信息层级、克制动效、统一圆角和单一强调色。产品身份图、工厂图和编辑图分开管理。AI 生图只能用于明确标记的背景、概念场景或装饰，不得冒充真实产品、工厂、客户、认证或评价；每个文件保存提示词、日期、用途、许可状态和 asset-manifest 记录，人工确认后才公开。

## 九、质量、SEO 与安全

WCAG 2.2 AA；移动端首屏 LCP 目标小于 2.5 秒；响应式图片、懒加载、加载/错误/空结果/离线购物车状态齐全。批准产品、面包屑和组织数据使用结构化数据；未经 SEO 决策的筛选 URL 和详情页 noindex。Lint、TypeScript、测试、Webpack build、桌面/移动浏览器冒烟通过后，才可宣称可发布。产品、价格、订单、支付、询价和发布变更保留审计日志。

## 十、仓库整理规则

`app/` 只放路由与页面；`components/` 放可复用 UI；`data/` 放批准数据和 fixture；`lib/` 放领域逻辑；`docs/` 放需求、决策、门禁和运行手册；`research/` 放只读研究；`assets/` 与 `public/` 分离原始/派生媒体。历史阶段文档、来源哈希、审阅记录和 `.product-ingestion/` 不因看起来重复而删除。只有引用关系、构建和测试都确认的死文件才可删除；重命名要保留兼容跳转。所有现有未提交产品/素材变更必须保留，不擅自提交、推送、部署或修改 DNS。

## 十一、现在直接执行的内容与暂缓内容

现在直接执行：中文需求核对、仓库审计、目录筛选 UI、URL 状态、产品卡、详情交互、本地购物车/RFQ adapter、响应式与可访问性修复、测试、构建和浏览器验证。暂缓但已定义接口：Supabase 项目、Stripe 账户、邮件供应商、Google 登录、真实价格/MOQ/库存、税费物流、域名/DNS、生产部署、正式评价和分析平台；它们需要外部凭据、业务事实或人工授权。
