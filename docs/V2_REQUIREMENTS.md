# JS Meilai 2.0 实施说明

状态：2.0 基线已并入 2.1；最新实施和外部待办见 [2.1 发布记录](V2_1_RELEASE.md)。

本文记录用户在已接受的 1.0 记录基础上提出的 2.0 调整需求。历史 1.0 报告和验收记录保持不变，继续说明各自原有的检查点。

## 0. 2.1.5 多语言界面基础

在 2.2 SEO/GSC 基线之后，仓库增加了一个受控的客户端语言选择基础，当前支持英语、简体中文、德语、法语和意大利语。语言选择器、公告、导航、页脚、首页核心文案、目录操作文案、集合页采购操作文案和询价表单会随选择切换，并将选择保存在浏览器中。实现和边界见 [2.1.5 多语言界面记录](V2_1_5_LOCALE_UI.md)。

该基础层不创建可索引的语言路由，不增加 hreflang、localized canonical 或多语言 sitemap。完整的逐页翻译和多语言 SEO 属于 2.3，需先完成术语、事实、法律文案和 URL 归属的人工审核；2.2 的正式索引和技术 SEO 发布边界保持不变。

## 1. 1.0 基线审计

仓库已有清晰的 Next.js App Router 结构：`app/` 负责路由和 API 处理器，`components/` 负责可复用界面组件，`data/` 负责已批准产品目录，`lib/` 负责业务逻辑与服务商适配器，`supabase/` 负责数据库迁移，`tests/` 覆盖当前功能边界。1.0 基线通过了 49 个测试、TypeScript 类型检查、ESLint 检查和 Webpack 构建。

纳入 2.0 处理的 1.0 问题包括：

- 公告条为静态内容，缺少易读的轮播或滚动效果；
- 产品目录 URL 接受 `search` 参数，但界面没有可用的搜索框，也没有应用该参数；
- 筛选项仅根据现有记录生成，导致尚无对应产品时无法展示主流颜色分类；
- 产品系列导航不一致：网站有六个系列方向，但页脚缺少戏服／舞台手套（Costume / Stage gloves）；
- 商品详情需要更完整的颜色、材质、尺码、定制、包装和采购信息区域，并明确各项信息的确认状态；
- 后台功能可用，但视觉密度较高，状态层级不清晰，移动端体验有待完善；
- 本地已批准资产与数据库媒体之间缺少清晰的运行时边界；
- Paddle 和 Stripe 仍作为历史基础设施保留，并在条件不满足时停止操作，但两者均非 2.0 选定的支付方案；
- 工厂页面存在一处中文标点，不符合公开界面全英文的要求。

## 2. 已实施的 2.0 范围

### 仓库与文档

- 完整保留历史阶段和验收记录，仅清除操作系统杂项文件或已确认不再使用的文件。
- 以 `README.md`、`DESIGN.md` 和本文作为快速入口。溯源、迁移、研究和本地导入证据继续保存在各自所属目录。
- 在 `DESIGN.md` 中记录选定的视觉参考、设计变量、响应式规则、动效边界和后台规则。

### 公开产品目录

- 增加可见的产品搜索框，支持从 URL 恢复搜索状态，并可检索名称、系列、材质、颜色、风格、场合、装饰和描述。
- 首页、导航、页脚和产品目录中，六个系列入口保持同等权重。
- 即使当前产品数量为零，也展示完整颜色分类：黑色（black）、白色（white）、象牙色（ivory）、裸色（nude）、香槟色（champagne）、红色（red）、粉色（pink）、蓝色（blue）、绿色（green）、紫色（purple）、棕色（brown）、金色（gold）、银色（silver）和定制色（custom）。零结果选项显示数量，并为后续数据库产品保留入口。
- 在已批准数据支持的情况下，扩展场合、装饰和年龄段筛选。
- 保留多选交集、URL 状态、结果数量、排序、已选条件标签、一键清除、移动端抽屉、最近浏览和空结果恢复功能。
- 产品卡片和商品详情仅使用已批准图片与已确认字段。商品详情为未来的产品变体、样品、包装和定制配色预留空间，不虚构供货情况。

### 定制生产

- 将定制／代工（OEM）路径作为导航、首页、商品详情和结账文案中的主要入口。
- 明确颜色、结构、尺码、标志、包装和来料方案需要逐项目评审，不能暗示所有方案自动可行或存在固定起订量。

### 后台与媒体

- 后台增删改查继续由 Supabase 身份认证和服务端角色检查授权。
- 产品图片上传至受保护的 `product-media` 对象存储桶，并由数据库产品记录引用。关联的 Supabase 项目已包含迁移后的 36 个已批准并上架的产品，以及 137 个已批准的网页媒体对象。`COMMERCE_CATALOG_ENABLED=true` 会关闭本地产品目录回退，使数据库故障时停止提供目录，而不是静默使用仓库图片。
- 后台必须明确展示草稿、已上架、已归档、待复核和服务商不可用状态，支持移动端操作，并清晰呈现发布复核步骤。
- Supabase 的泄露密码保护告警在 2.1 复查中仍然存在。该功能需要 Pro 及以上套餐，本次没有擅自升级付费套餐；应用要求新密码至少 12 位，并限制账号邮件和确认请求频率。

### 支付决策

2.0 支付候选方案为 **PayPal PPCN 商业账户（Business）／确认报价后结账（Checkout）**。对于中国大陆运营、面向海外买家的业务，PayPal 官方中国文档明确支持接收中国大陆以外买家的商业付款，以及外币收款后结算为人民币，因此最适合作为首个候选方案。收单、结汇和提现费用分别以实际开户协议为准。PayPal 仍要求企业核验和真实贸易背景，因此网站继续以询价为先：买家收到已确认报价后，再获取 PayPal 订单或付款链接，不能按未经确认的目录价格直接付款。

万里汇是较强的跨境收款和资金管理选项，但其公开材料主要面向全球账户、平台收款或付款链接收款，而非小型独立站结账。连连支付提供跨境收单服务，但正式实施前需要通过商户方案确认入网条件、支持国家、银行卡支付方式、结算和风控条款。两者均作为已评估的备选方案保留，不作为隐藏的备用支付服务商。

代码边界如下：

1. 先通过报价／询价流程确认商业信息，并创建服务端订单；
2. 结账路由仅接受该订单 ID，在服务端重新读取订单明细和总额；只有商户凭据和已批准报价均存在时，PayPal 适配器才创建订单；
3. 验证 PayPal 事件回调后更新支付状态，始终不信任浏览器提交的金额；
4. 缺少凭据时停止支付，并明确显示“PayPal 正在等待商户核验”的状态。

## 3. 2.1 承接结果

- Supabase 迁移、访问策略、后台产品和库存、询价和报价流程已进入 2.1 实际验收。
- 173 个产品派生图已在云端核对哈希，产品图片二进制已移出仓库；公开产品引用其中 137 张。
- 两个管理员邮箱、密码恢复、邀请与生产配置由 2.1 发布记录统一记录。
- PayPal 开户由用户明确延后，待取得工厂资料后完成；沙盒、生产交易、回调、退款和结算验收仍待正式商户环境。
- 价格、MOQ、库存、生产周期、运费和税费由工厂按具体询价确认。后台已提供字段和确认状态，不虚构商业承诺。
- 当前公告滚动使用 CSS，没有需要 GSAP 编排的复杂交互，因此没有添加额外动效运行时。

## 4. 验收门槛

- 公开界面文本扫描不含中文字符；
- 桌面端和移动端导航中的搜索及六个系列链接均可用；
- 当前结果数量为零时，颜色选项仍然可见；
- 刷新后可恢复查询参数，筛选交集产生预期的结果数量；
- 商品详情展示已批准媒体、已确认属性、定制说明和真实可用的询价路径；
- 后台未登录时显示清晰的状态；在已授权环境中支持“保存 → 复核 → 发布／归档”，且不暴露服务密钥；
- 本地溯源文件仅作为证据；电商目录开关开启时，已验证的运行时目录读取 Supabase 媒体；
- 在宣布 2.0 检查点完成前，记录 `npm test`、`npm run typecheck`、`npm run lint`、`npm run build` 的结果，以及 Chrome 桌面端和移动端的观察记录。
