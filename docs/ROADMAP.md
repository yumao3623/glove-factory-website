## 候选 2.3.0：英文采购内容与询价转化

**目标 / 为什么：** 让 B2B 买家有充分信息判断供应商和提交可报价询盘。实查工厂与定制页仅少量泛化段落，36 个产品扩展规格为空；先改善事实与转化，再放大多语言流量。

**启动条件 / 依赖：** 先形成已批准事实包、选定首批 6–10 个商业优先产品（按供货能力/真实采购需求选，不为凑六类）、明确询价负责人和响应流程；确认需要页面结构/信息呈现/询价流程的成套开发。仅补现有字段能解决的，按内容运营完成，不强造 MINOR。无需以 Google 收录为硬前提。

**Scope：** 基于证据完善 factory 与 custom 的身份、流程、样品/质量/定制能力说明；首批 PDP 的材质、尺寸/测量、颜色、样品、包装、MOQ/交期逐项区分已确认与需询价；优化采购 CTA 和上下文；复用已有后台状态与报价。为新增合格英文页面逐页决定 canonical/indexability/sitemap，costume 独立 gate 保留。

**Definition of Done：** 选定页面与首批产品都有事实来源/负责人；未知信息不虚构；桌面/移动能完成带正确产品与数量的询价；受控验收验证存储→邮件平台送达→后台跟进→报价；失败不丢单；新索引页通过技术审计；相关测试及 Git/main/Production 部署证据齐全。若验收会发邮件，任务需明确授权测试收件人。

**不做：** 全站重构、批量解除 noindex、翻译所有产品、自动 CRM、支付上线、承诺认证/销量/交期。

## 候选 2.4.0：有目标市场的完整多语言 SEO

**目标 / 为什么：** 把经过验证的英文采购内容扩展至有商业需求的目标语言；这是独立能力，值得 MINOR，但五语言 UI 本身不证明五个市场都值得投入。

**启动条件 / 依赖：** 英文核心内容成熟；至少一个目标语言有来自询盘、经营者市场策略或 GSC 的明确需求；每个上线语言有翻译/事实/法律审核负责人和长期维护预算。GSC 非唯一决策来源。路线冻结后才决定具体首批语言；当前五语言 UI 可继续保留。

**Scope：** 独立可抓取语言 URL，服务端真实本地化核心内容，逐页 localized metadata/self canonical、双向 hreflang（含明确默认策略）、语言 sitemap 与未翻译页回退/不索引策略，结构化数据与分语言 GSC 检查，迁移/回滚。

**Definition of Done：** 每个上线语言的核心采购流程完整且人工审核；无空白/机械重复索引页面；canonical/hreflang 对称正确；默认英文 URL 和转化不回归；发布后抽样抓取与 GSC 检查，后者数据延迟不伪装已收录。测试、部署、生产验收记录齐全。

**不做：** 只翻 metadata 就宣称多语言 SEO、未经审核机器翻译商业事实、强制一次上线四种新语言、同时改支付或品牌定位。

## 候选后续 MINOR：确认报价后的 PayPal 正式支付（暂不占定版本号）

**目标 / 为什么：** 在真实买家需要时减少已批准报价的付款摩擦。当前是 RFQ 优先的 B2B 站，SQL 尚无询价/订单，支付不是最高优先级。

**启动条件 / 依赖：** 经营者完成企业账户/KYC/收单与结算确认；存在明确付款场景；运费、税费、退款、库存/交期等商业条款可正式确认。可先完成商户材料，不让未就绪审核占住开发版本。

**Scope：** 复用现有代码，验证真实 sandbox create→approve→capture，webhook 验签、金额/币种、重复与乱序幂等、取消/超时/失败/退款；生产凭据、webhook 和受控生产验收，到账/结算核对及回滚开关。

**Definition of Done：** 沙盒成功与失败矩阵有证据；生产订单/支付事件对应准确；真实付款与结算由经营者完成并确认；邮件/后台状态一致；上线开关与监控/退款负责人明确。代码测试或数据库模拟不能替代支付商验收。

**不做：** 仅将 false 改 true 就称发布、从目录未确认价直接结账、并行接多家支付、擅自代签协议或付款。

**版本判断：** 首次把在线付款交付给买家属于新能力，通常单独 MINOR（届时按实际顺序分配），不是补做 2.2。日后已经验收的支付功能仅例行重新启用属于 Operations；小 bug 才 PATCH。若真实成交需求先出现可记录依据后调整排序，不重编号历史。
