# B2B SEO Adaptation of `SEO_GUIDE.md`

The source guide is written for AI tools and SaaS. Its principles are retained only where they fit a manufacturing catalogue and enquiry journey.

## DIRECTLY_APPLICABLE

- Search intent before keywords and one canonical owner per intent.
- Information gain from first-party product, material, process, packaging, sample and factory evidence.
- Stable lowercase URLs, canonical, redirects, robots, sitemap, hreflang and mobile-first rendering.
- Unique titles, meta descriptions, one H1 and coherent H2/H3 hierarchy.
- Image SEO: useful product imagery, descriptive alt text, intrinsic dimensions, modern formats and lazy loading.
- Contextual internal links between product hubs, product pages, OEM/custom pages, factory evidence and contact/request-quote pages.
- Truthful JSON-LD using relevant types such as Organization, Product, CollectionPage, BreadcrumbList and FAQPage only when visible and supported.
- Core Web Vitals, crawl/index monitoring, Search Console and analytics after launch.
- Backlink quality based on relevance, authority and audience precision; no indiscriminate directory submission.
- Pre-launch, launch and post-launch validation checklists.
- No fabricated claims, ratings, customers, certifications, capacity or dates.

## NEEDS_ADAPTATION

| SaaS framing in source | B2B manufacturing adaptation |
| --- | --- |
| Tool / feature page | Product category, product detail or custom manufacturing page. |
| Try / sign up / checkout | Request a quote, request samples, contact sales or download a specification sheet. |
| Product proof | Product close-ups, material details, stitching/finishing, packaging, sample workflow and permitted factory evidence. |
| ICP | Importer, wholesaler, bridal shop, occasionwear brand, distributor, e-commerce seller and sourcing agent. |
| Pricing page | MOQ, sample terms, lead-time ranges and quote workflow only when confirmed; avoid invented price tables. |
| Use-case page | Bridal retail, eveningwear, events/costume and private-label sourcing when each has distinct evidence. |
| Feature comparison | Material/style/length/customization comparison, with explicit methodology and no unsupported competitor claims. |
| Product analytics | Qualified enquiries, sample requests, quote requests, product-page engagement and assisted conversions. |
| SoftwareApplication schema | Organization/Product/CollectionPage/BreadcrumbList/FAQPage as truthful page types. |

## NOT_APPLICABLE

- AI tool pages, software feature matrices, API documentation, model/provider claims, SaaS trials, user accounts, subscription pricing and software onboarding flows.
- Programmatic city/model/version pages without genuinely different product data.
- Fake reviews, fabricated customer logos, invented case studies or synthetic performance statistics.

## B2B page principles

1. Put the product family and buyer outcome above the fold; use a clear Request Quote path.
2. Answer procurement questions early: materials, sizing, customization, MOQ, sample process, lead time and packaging, but only with verified values.
3. Make evidence inspectable: original images, process notes, downloadable specs and named update dates where real.
4. Separate commercial investigation from informational education; do not make a generic blog page compete with a product category.
5. Keep one primary intent per canonical URL and link buyers to the next operational step.
