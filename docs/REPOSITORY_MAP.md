# 仓库结构说明

仓库保持为一个 Next.js 应用。历史阶段报告和验收记录保留原路径，因为它们属于证据记录，不是重复的运行时代码。

```text
app/                 路由、布局、元数据和 API 处理器
components/          按布局、营销、产品、账户、后台和询价分组的可复用界面组件
data/                已批准产品目录、系列分类、测试样例和媒体引用
lib/                 业务逻辑与服务商适配器（电商、认证、导入、展示）
types/               共享的 TypeScript 业务类型
assets/              资产清单，以及为溯源保留的原始和派生媒体
public/              已批准用于预览、可由浏览器访问的派生资源
supabase/            纳入版本管理的数据库迁移和访问策略
scripts/             导入、校验和审计工具
tests/               边界、数据、路由和服务商测试
docs/                当前需求、决策、验收记录、操作手册和本结构说明
research/            只读的竞品、关键词、搜索引擎优化、工厂和视觉研究资料
.product-ingestion/  不纳入 Git 的本地原始归档和草稿审阅状态
```

2.0 的运行时职责限定如下：

- 公开产品目录通过 `lib/commerce/catalog.ts` 读取；
- 数据库产品和受保护图片通过 Supabase REST 接口及对象存储适配器接入；
- 本地已批准产品目录仅在电商目录开关关闭时作为迁移和测试的备用数据源；已验证的远程项目已写入 36 条已上架记录和 137 个受保护媒体对象；
- 管理员修改通过 `app/api/admin/*` 接口执行，并由 `lib/commerce/admin.ts` 校验；
- 支付适配器从不信任客户端金额，缺少商户配置时停止支付操作。

根目录中的阶段报告不会被删除或静默合并。只有在 `rg` 确认没有导入或引用、删除后构建和测试仍然通过，并且相关证据已保留在所属文档或被明确取代时，才可删除文件。
